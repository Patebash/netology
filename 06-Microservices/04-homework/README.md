# Домашнее задание к занятию "Микросервисы: масштабирование"

*Вы работаете в крупной компании, которая строит систему на основе микросервисной архитектуры. Вам как DevOps-специалисту необходимо выдвинуть предложение по организации инфраструктуры для разработки и эксплуатации.*

## Задача 1: Кластеризация
> Предложите решение для обеспечения развёртывания, запуска и управления приложениями. Решение может состоять из одного или нескольких программных продуктов и должно описывать способы и принципы их взаимодействия.
> Решение должно соответствовать следующим требованиям:
> * поддержка контейнеров;
> * обеспечивать обнаружение сервисов и маршрутизацию запросов;
> * обеспечивать возможность горизонтального масштабирования;
> * обеспечивать возможность автоматического масштабирования;
> * обеспечивать явное разделение ресурсов, доступных извне и внутри системы;
> * обеспечивать возможность конфигурировать приложения с помощью переменных среды, в том числе с возможностью безопасного хранения чувствительных данных таких как пароли, ключи доступа, ключи шифрования и т. п.
> 
> Обоснуйте свой выбор.

## Ответ:

Для этой задачи практически эталонным решением является **Kubernetes**. Оно полностью соответствует всем перечисленным требованиям и является отраслевым стандартом для управления контейнеризированными приложениями.

Для развёртывания, запуска и управления микросервисными приложениями предлагается использовать следующий стек:

* **Kubernetes** — оркестрация контейнеров;
* **Docker** — контейнеризация приложений;
* **Ingress Controller (NGINX Ingress)** — маршрутизация внешнего трафика;
* **CoreDNS** — обнаружение сервисов (Service Discovery);
* **Horizontal Pod Autoscaler (HPA)** — автоматическое масштабирование;
* **ConfigMap** и **Secret** — хранение конфигурации и чувствительных данных.

## Как выполняются требования

### Поддержка контейнеров

Приложения упаковываются в Docker-контейнеры и развёртываются в Kubernetes в виде Pod.

---

### Обнаружение сервисов

Каждому приложению соответствует объект **Service**, который получает постоянное DNS-имя. Благодаря **CoreDNS** микросервисы могут обращаться друг к другу по имени, например:

```text
http://user-service
```

без необходимости знать IP-адреса.

---

### Маршрутизация запросов

Внешние запросы поступают через **NGINX Ingress Controller**, который по заданным правилам направляет их к нужному сервису.

Например:

```text
/api/users    → user-service
/api/orders   → order-service
/api/payment  → payment-service
```

---

### Горизонтальное масштабирование

Kubernetes позволяет увеличить количество экземпляров приложения (Pod), например с двух до пяти, чтобы распределить нагрузку между ними.

---

### Автоматическое масштабирование

**Horizontal Pod Autoscaler (HPA)** автоматически изменяет количество Pod в зависимости от нагрузки (например, загрузки процессора или использования памяти). Это позволяет эффективно использовать ресурсы без ручного вмешательства.

---

### Разделение внутренних и внешних ресурсов

Kubernetes предоставляет разные типы сервисов:

* **ClusterIP** — сервис доступен только внутри кластера;
* **NodePort** и **LoadBalancer** — сервис доступен извне;
* **Ingress** — единая точка входа для внешнего трафика.

Это позволяет изолировать внутренние сервисы и публиковать только необходимые компоненты.

---

### Конфигурация приложений

Для хранения параметров конфигурации используются **ConfigMap**. Переменные автоматически передаются приложениям через переменные окружения.

Например:

```text
DATABASE_HOST=db-service
LOG_LEVEL=INFO
```

---

### Хранение секретов

Пароли, токены и ключи доступа хранятся в объектах **Secret** и передаются приложениям безопасным способом. Это исключает необходимость хранить чувствительные данные в исходном коде или конфигурационных файлах.

---

## Обоснование выбора

Для управления контейнеризированными приложениями предлагается использовать **Kubernetes**.

Данное решение полностью соответствует требованиям задания:

* ✅ поддерживает запуск Docker-контейнеров;
* ✅ обеспечивает обнаружение сервисов с помощью Service и CoreDNS;
* ✅ предоставляет маршрутизацию запросов через Ingress Controller;
* ✅ поддерживает горизонтальное и автоматическое масштабирование приложений;
* ✅ позволяет разделять внутренние и внешние сервисы;
* ✅ предоставляет механизмы управления конфигурацией (ConfigMap) и безопасного хранения секретных данных (Secret).

Кроме того, Kubernetes является отраслевым стандартом для построения отказоустойчивых и масштабируемых микросервисных систем и широко используется в облачных и корпоративных инфраструктурах.

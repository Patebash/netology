# Домашнее задание к занятию "Микросервисы: принципы"

*Вы работаете в крупной компании, которая строит систему на основе микросервисной архитектуры. Вам как DevOps-специалисту необходимо выдвинуть предложение по организации инфраструктуры для разработки и эксплуатации.*

## Задача 1: API Gateway

> Предложите решение для обеспечения реализации API Gateway. Составьте сравнительную таблицу возможностей различных программных решений. На основе таблицы сделайте выбор решения.
> Решение должно соответствовать следующим требованиям:
> * маршрутизация запросов к нужному сервису на основе конфигурации,
> * возможность проверки аутентификационной информации в запросах,
> * обеспечение терминации HTTPS.
> 
> Обоснуйте свой выбор.

## Ответ:

### Для реализации API Gateway рассмотрим несколько популярных решений:
* NGINX
* Kong
* Traefik
* HAProxy

### Анализ решений

#### NGINX

Преимущества:
* высокая производительность;
* простая настройка;
* поддержка HTTPS;
* балансировка нагрузки;
* широкое распространение.

Недостатки:
* для полноценного API Gateway требуется настройка дополнительных модулей;
* отсутствует встроенная система управления API.

---

#### Kong

Преимущества:
* специально разработан как API Gateway;
* встроенная проверка JWT, OAuth2 и API Key;
* большое количество готовых плагинов;
* удобное масштабирование;
* хорошая интеграция с Kubernetes и Docker.

Недостатки:
* более сложная настройка;
* требует дополнительных компонентов (например, базы данных или работы в DB-less режиме).

---

#### Traefik

Преимущества:
* автоматическое обнаружение сервисов;
* удобная интеграция с Docker и Kubernetes;
* простая настройка сертификатов Let's Encrypt.

Недостатки:
* меньше возможностей по управлению API, чем у Kong;
* часть функций реализуется через middleware.

---

#### HAProxy

Преимущества:
* очень высокая производительность;
* отличная балансировка нагрузки;
* надежность.

Недостатки:
* ориентирован прежде всего на балансировку трафика;
* функции API Gateway реализованы ограниченно.

---

### Выбор решения

Для указанных в задании требований наиболее подходящим является **Kong**.

### Обоснование выбора

Kong полностью соответствует требованиям задания:

* ✅ выполняет маршрутизацию запросов к нужным микросервисам;
* ✅ поддерживает проверку аутентификации (JWT, OAuth2, API Key);
* ✅ обеспечивает HTTPS-терминацию;
* ✅ поддерживает балансировку нагрузки;
* ✅ имеет большое количество готовых плагинов;
* ✅ хорошо масштабируется и подходит для микросервисной архитектуры.

Для организации API Gateway предлагается использовать **Kong**, поскольку он обеспечивает все необходимые функции: маршрутизацию запросов, проверку аутентификации, HTTPS-терминацию и дополнительные возможности (балансировка нагрузки, ограничение числа запросов, логирование и мониторинг). Это решение хорошо подходит для эксплуатации крупных микросервисных систем и позволяет упростить дальнейшее развитие инфраструктуры.

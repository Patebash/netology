# Домашнее задание к занятию «Компоненты Kubernetes»

## Задание. Необходимо определить требуемые ресурсы
> Известно, что проекту нужны база данных, система кеширования, а само приложение состоит из бекенда и фронтенда.
> Опишите, какие ресурсы нужны, если известно:
> 1. Необходимо упаковать приложение в чарт для деплоя в разные окружения.
> 2. База данных должна быть отказоустойчивой. Потребляет 4 ГБ ОЗУ в работе, 1 ядро. 3 копии.
> 3. Кеш должен быть отказоустойчивый. Потребляет 4 ГБ ОЗУ в работе, 1 ядро. 3 копии.
> 4. Фронтенд обрабатывает внешние запросы быстро, отдавая статику. Потребляет не более 50 МБ ОЗУ на каждый экземпляр, 0.2 ядра. 5 копий.
> 5. Бекенд потребляет 600 МБ ОЗУ и по 1 ядру на копию. 10 копий.

## Ответ:

### 1. Расчёт всех необходимых ресурсов:

Сначала считаем ресурсы самого приложения, без учёта Kubernetes, нод и запаса.

Исходные данные:

| Компонент   | RAM на экземпляр | CPU на экземпляр |  Копии |    Всего RAM |  Всего CPU |
| ----------- | ---------------: | ---------------: | -----: | -----------: | ---------: |
| База данных |             4 ГБ |            1 CPU |      3 |        12 ГБ |      3 CPU |
| Кеш         |             4 ГБ |            1 CPU |      3 |        12 ГБ |      3 CPU |
| Frontend    |            50 МБ |          0.2 CPU |      5 |       250 МБ |      1 CPU |
| Backend     |           600 МБ |            1 CPU |     10 |         6 ГБ |     10 CPU |
| **Итого**   |                  |                  | **21** | **30.25 ГБ** | **17 CPU** |

*Таким образом, для работы приложения требуется минимум 17 CPU и 30.25 ГБ RAM.*

---

### 2. Определяем количество рабочих нод, которые справятся с нагрузкой:

Пока не учитываем отказ ноды и служебные ресурсы, считаем только ресурсы для приложения.
Всего по ресурсам нам нужно:

```
17 CPU
30,25ГБ RAM
```
Для расчёта возьмём, например, worker-ноду:

```
8 CPU
16 ГБ RAM
```

Для того чтобы обеспечить работу приложения таких **worker-нод необходимо 3 штуки**:

**CPU:**

*Для работы приложения нужно 17, 8 x 3 =24. Достаточно 3 ноды, даже с запасом.*

**RAM:**

*Для приложения нужно 30,25ГБ, 16 x 3 =48. Так же берем с запасом*.

**Сравниваем:**

| Ресурс | Нужно приложению | 3 ноды |     Запас |
| ------ | ---------------: | -----: | --------: |
| CPU    |               17 |     24 |        +7 |
| RAM    |         30.25 ГБ |  48 ГБ | +17.75 ГБ |

**Итог:**

> **3 worker-ноды по 8 CPU / 16 ГБ RAM.**

---

### 3. Добавляем запас на отказ одной ноды:

Если теряем одну ноду, получаем отказ по CPU:

| Ресурс | Требуется | После отказа 1 ноды | Результат          |
| ------ | --------: | ------------------: | ------------------ |
| CPU    |        17 |                  16 | ❌ Не хватает 1 CPU |
| RAM    |  30.25 ГБ |               32 ГБ | ✅ Хватает          |

Для отказоустойчивости берём еще одну ноду **8CPU 16RAM**

Итого получаем:

```
4 worker-ноды
8 CPU
16 ГБ RAM
```
*При отказе одной ноды мы получим 24 CPU и 48RAM. Этого достаточно для приложения.*

---

### 4. Добавляем служебные ресурсы нод:

> На каждой worker-ноде работают:
> 
> * операционная система;
> * kubelet;
> * container runtime;
> * CNI;
> * kube-proxy или его аналог;
> * системные Pod;
> * мониторинг;
> * логирование и т.д.
> 
> Поэтому часть ресурсов необходимо зарезервировать.

Так как фактическое потребление системных компонентов Kubernetes неизвестно, для предварительного расчёта зарезервируем **1 CPU и 4 ГБ RAM** на worker-ноду.
Это упрощённая оценка для задания. В реальном кластере величина зависит от ОС, Kubernetes-дистрибутива и установленных системных компонентов.

Итоговая таблица с потреблением служебных ресурсов:

**4 worker-ноды по 8 CPU / 16 ГБ RAM**

| Ресурс | Требуется приложению | Системный резерв | Физически доступно |        Запас |
| ------ | -------------------: | ---------------: | -----------------: | -----------: |
| CPU    |               17 CPU |            4 CPU |             32 CPU |   **11 CPU** |
| RAM    |             30.25 ГБ |            16 ГБ |             64 ГБ  | **17.75 ГБ** |

После отказа одной ноды:

**Остаётся 3 worker-ноды**

| Ресурс | Требуется приложению | Системный резерв | Физически доступно |        Запас |
| ------ | -------------------: | ---------------: | -----------------: | -----------: |
| CPU    |               17 CPU |            3 CPU |             24 CPU |    **4 CPU** |
| RAM    |             30.25 ГБ |            12 ГБ |              48 ГБ | **5.75 ГБ** |

---

### 5. Количество нод и их параметры:

| Тип           | Количество |   CPU |   RAM |
| ------------- | ---------: | ----: | ----: |
| Worker node       |          4 | 8 CPU | 16 ГБ |

> Но запас по RAM после отказа получается всего 5.75 ГБ, поэтому я бы для реального проекта рассмотрел ещё промежуточный вариант — например, 8 CPU / 24 ГБ RAM. Он даст более комфортный запас.

*Примечание для production:*
В реальном Kubernetes-кластере дополнительно необходимо учитывать control-plane-ноды.

Например:

| Тип           | Количество |   CPU |   RAM |
| ------------- | ---------: | ----: | ----: |
| Control-plane |          3 | 4 CPU |  8 ГБ |
| Worker        |          4 | 8 CPU | 16 ГБ |

> При этом **4 CPU / 8 ГБ для control-plane** — это предварительное допущение. В реальном проекте смотрят по фактической нагрузке kube-apiserver, scheduler, controller-manager, etcd и системных компонентов.

Таким образом, полный кластер будет состоять из **3 control-plane и 4 worker-нод**. Ресурсы control-plane в основном расчёте задания не учитываются, поскольку их требования не заданы в условии.
